Note

Password-locked web sections

A recruiter should be able to open a confidential case study. A random visitor should not. That is a gate, not a vault.

I used one on my Sanex write-up. The password goes in the job application. The form has a real label, a password field, a button, and an error next to the field if they miss. Once they get in, this tab stays unlocked until they close it.

Try the gate

This is a teaching copy. Password: try-me

Incorrect password. Hint: try-me

You are in. For a portfolio, this is enough: it slows down casual clicks and still lets a hiring manager through.

It is not security. Anyone can view the page source. Do not put client originals, private data, or anything harmful behind a front-end check like this. If it must stay private, keep it off the public site.

What I wanted

No extra server. No user accounts. A password I can paste into an application. An error that tells them what to do next, not “Error 401”.

What I would do next

For something more serious, the check would live on the server, and the protected files would not be public at all. For a UX case study, the polite gate was the right size of solution.
